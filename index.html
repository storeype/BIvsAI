Phase 2 findings · draft

Does AI make the BI tool unnecessary?

The hypothesis. If an AI can find the data, build the model and publish an interactive dashboard as a plain web page, the business-intelligence platform in the middle becomes unnecessary: the analyst no longer needs a BI tool to put a decision in front of a manager.

The test. Fourteen logistics briefs, each run to the same standard (real reference company, Excel model, data map, themed deck): eight on public data, including the main project, and six where the data a company would use is private, so the AI generated anchored synthetic data instead. For each: could a simple AI-built web dashboard serve the decision-maker, or does a BI tool add something the page cannot?

Answer: partly true, and the split follows the data. AI did the analytical work in all 14 briefs. On public data, an AI-built page was enough for 6 of 8 decisions. On the synthetic briefs it was enough for none: 3 are mixed and 3 favour a BI platform. The synthetic briefs are exactly the decisions that run on internal, frequently refreshed, shared data (terminal systems, equipment control, WMS, ERP). That is where BI still earns its place. AI replaces the BI developer’s work, not the platform.

When does the BI tool earn its place?

Refresh cadence

Annual or quarterly public data: re-run the page. Shift-by-shift, daily or twice-weekly decisions (3, 4, 14): scheduled refresh is the product.

Internal data

Every synthetic brief stands in for data a company holds and the public cannot see. Joining that data safely is what BI platforms do.

Many users

One manager deciding once a year needs a page. Planners, carriers, buyers and finance working one view need governed definitions and access control.

Audit trail

Pricing, rerouting, emissions reporting and working-capital calls get challenged later. Keeping what the numbers said is a platform feature.

The data exists, just not in public

The synthetic tables are stand-ins for data that real companies already hold in operational systems. Each brief’s workbook labels every generated field and documents how it was made (seed, parameters, checks against the real anchor).

Open questions in this draft

Synthetic verdicts are about the real-data version. On the generated tables an AI page works fine. The BI verdicts for briefs 3, 4, 9, 13, 15 and 18 describe what the decision would need with the company’s actual data, which is reasoned, not tested.
Synthetic data is never the finding. The rankings show how each decision rule behaves on plausible data. Where a pattern holds (high-value goods fly, long lanes dominate emissions, dwell spread drives safety stock), it traces back to the real anchor.
Self-assessed confidence. The confidence ratings and the BI verdicts come from the same AI that built the models. An independent review should confirm them.
Reasoned, not measured. Apart from the main project (built in Data Studio), no BI-tool versions were built, so “BI adds value” is argued from the decision’s needs, not measured in time, cost or user outcomes.
No ground truth. Only Brief 14 has a back-test against what actually happened.
The stronger test is still to come. These results compare BI with a static AI-built page. On public data the fairer opponent is an AI-built pipeline (scheduled refresh, alerts, git history as audit trail). See Next steps.
The draft dashboards re-weight, they do not recompute. Scores are frozen when the page is built, so changing a price or dataset means editing the workbook and republishing. A BI tool on a live sheet only needs an edit and a refresh. A page can also read a live published sheet, which would close this gap.
